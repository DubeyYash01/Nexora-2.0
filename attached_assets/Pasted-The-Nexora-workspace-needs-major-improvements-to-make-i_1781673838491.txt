FEATURE 2 — WIRING VALIDATOR
═══════════════════════════════════════

When user checks a connection 
that could be wrong:

Compare against known dangerous 
combinations:

const DANGEROUS_CONNECTIONS = [
  {
    component: 'any sensor',
    userPin: 'VCC',
    boardPin: 'GND',
    warning: 'Reversed power! This will 
      damage your sensor immediately.',
    severity: 'critical'
  },
  {
    component: 'any sensor', 
    userPin: 'GND',
    boardPin: '5V',
    warning: 'Wrong voltage! Most sensors 
      need 3.3V not 5V.',
    severity: 'critical'
  },
  {
    component: 'LED',
    userPin: 'anode',
    boardPin: 'GPIO without resistor',
    warning: 'Missing resistor! LED will 
      burn out without a resistor.',
    severity: 'warning'
  }
]

When dangerous connection detected:
  Show full-screen warning overlay:
  
  bg: rgba(255,90,90,0.15)
  border: 2px solid #FF5A5A
  border-radius: 16px
  padding: 32px
  max-width: 480px
  centered on screen
  
  Icon: alert-triangle 
        (64px, #FF5A5A, pulse animation)
  
  Heading: "⚠️ Connection Warning!"
  (color: #FF5A5A, bold, large)
  
  Subheading based on severity:
    critical: "This could damage 
               your hardware!"
    warning: "Double-check this 
              connection"
  
  Warning message (from DANGEROUS_CONNECTIONS)
  
  Correct connection shown:
    "It should be:"
    [correct connection diagram]
  
  Two buttons:
    "I'll fix it" (red primary)
      → closes overlay, unchecks 
        the wrong connection
    "I've already done it correctly"
      → closes overlay, marks done
  
  This popup appears immediately 
  when wrong connection is detected.
  Cannot be dismissed without 
  choosing an option.

Also use AI to validate combinations:
When user completes all connections 
in a step, before allowing 
"Complete Step":

Call POST /api/ai/validate-wiring:
  Body: {
    connections: [...user's connections],
    components: [...project components],
    platform: 'ESP32'
  }

AI checks for:
  - Power/ground reversals
  - Wrong voltage levels
  - Missing pull-up/down resistors
  - Pin conflicts (two components
    on same pin)
  - Communication bus conflicts

Returns:
  {
    safe: boolean,
    warnings: [...],
    critical: [...]
  }

If critical issues found:
  Block step completion
  Show warning overlay

  Show yellow warning
  Allow completion with confirmation

FEATURE 3 — SERIAL MONITOR
═══════════════════════════════════════

Add a "Serial Monitor" tab to 
the bottom AI panel area.

Tabs at bottom: 
[AI Assistant] [Serial Monitor]

Serial Monitor panel:

Header:
  "Serial Monitor"
  
  Connection status:
    Disconnected: gray dot "No device"
    Connected: green dot "ESP32 connected"
  
  "Connect Device" button:
    Uses Web Serial API
    Only works in Chrome
    
    On click:
    if (!('serial' in navigator)) {
      showToast({
        type: 'error',
        message: 'Serial Monitor requires 
          Chrome browser. Please open 
          Nexora in Chrome.'
      })
      return
    }
    
    try {
      const port = await 
        navigator.serial.requestPort()
      await port.open({ 
        baudRate: 115200 
      })
      setConnected(true)
      setSerialPort(port)
      startReading(port)
    } catch (err) {
      console.error(err)
    }
  
  Baud rate selector:
    Dropdown: 9600 | 115200 | 57600
    Default: 115200

Serial output area:
  bg: #0D0D14
  font-family: JetBrains Mono
  font-size: 13px
  color: #00C896
  padding: 12px
  height: 200px
  overflow-y: auto
  auto-scrolls to bottom
  
  Each line shows:
    timestamp (gray) + output (green)
    e.g. "[10:23:45] Temperature: 28.5°C"
  
  If error output (contains "Error"):
    color: #FF5A5A

Reading function:
async function startReading(port) {
  const reader = port.readable.getReader()
  const decoder = new TextDecoder()
  
  try {
    while (true) {
      const { value, done } = 
        await reader.read()
      if (done) break
      
      const text = decoder.decode(value)
      addLine(text)
    }
  } catch (err) {
    console.error('Serial read error:', err)
    setConnected(false)
  } finally {
    reader.releaseLock()
  }
}

Send command input:
  At bottom of serial monitor
  Text input + Send button
  Sends text to device via serial

Clear button: clears output

Save log button: downloads as .txt

FEATURE 6 — CONNECTION DIAGRAM VISUAL
═══════════════════════════════════════

For each wiring step, generate a 
simple ASCII/SVG connection diagram.

When build plan is generated by AI,
also generate wiring for each step.

Add to build plan generation prompt:

"For each step with wiring, include:
'wiringDiagram': [
  {
    from: { component: 'DHT22', pin: 'DATA' },
    to: { component: 'ESP32', pin: 'GPIO 4' },
    wireColor: 'yellow',
    critical: false
  },
  {
    from: { component: 'DHT22', pin: 'VCC' },
    to: { component: 'ESP32', pin: '3.3V' },
    wireColor: 'red',
    critical: true,
    warning: 'Use 3.3V not 5V'
  }
]"

Display as visual table with 
colored wire indicators:
  Red wire = power (VCC)
  Black wire = ground (GND)
  Yellow/colored = data/signal
  Orange = analog
  Green = I2C/SDA
  Blue = I2C/SCL

Each wire row shows the color 
as a small colored circle.
