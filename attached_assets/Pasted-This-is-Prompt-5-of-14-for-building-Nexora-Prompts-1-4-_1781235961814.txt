═══════════════════════════════════════
UNDERSTANDING THE CORE VALUE HERE
═══════════════════════════════════════

This is the feature that saves students 
money and prevents wasted purchases.

The problem it solves:
  Student buys wrong component → ₹200 wasted
  Student buys duplicate → ₹300 wasted
  Student doesn't know alternatives → 
    waits 3 days for delivery
  
  Nexora solves all three.

The "Build With What You Own" feature is 
also a powerful acquisition hook:
  User adds their components → 
  Nexora suggests 5 projects they can 
  build TODAY with zero extra spending →
  User feels immediate value →
  User upgrades to paid tier

New table: user_components
  id              uuid (gen_random_uuid(), pk)
  user_id         uuid (references profiles.id)
  name            text
  category        text 
    (values: 'microcontroller' | 'sensor' | 
     'actuator' | 'display' | 'communication' |
     'power' | 'passive' | 'module' | 'other')
  quantity        integer (default 1)
  condition       text 
    (values: 'new' | 'working' | 
     'untested' | 'faulty')
  purchase_price  numeric (nullable)
  notes           text (nullable)
  added_at        timestamp with time zone
  last_used_at    timestamp with time zone (nullable)

New table: project_budget
  id              uuid (gen_random_uuid(), pk)
  project_id      uuid (references projects.id)
  user_id         uuid (references profiles.id)
  budget_limit    numeric (nullable)
  components      jsonb
    (array of:
     {
       componentId: string,
       name: string,
       estimatedCost: number,
       actualCost: number (nullable),
       owned: boolean,
       quantity: number,
       purchaseLink: string (nullable),
       purchased: boolean
     }
    )
  total_estimated numeric
  total_actual    numeric (default 0)
  created_at      timestamp with time zone
  updated_at      timestamp with time zone

RLS on both tables:
  Users can only access their own rows.

COMPONENT SUBSTITUTION ENGINE
═══════════════════════════════════════

Triggered from:
  1. Build step wiring notes 
     (when AI mentions a component)

     any component in a project

     "What if I don't have [component]?"

For cases 1 and 2, a dedicated UI:

Small inline card that appears below 
the component in question:

  Heading: "Don't have [component name]?"
  
  Loading: calls Gemini for substitutions
  
  Gemini prompt (fast, targeted):
  "For an IoT project using [platform], 
   suggest 2-3 substitutes for [component].
   User's available components: 
   [user inventory list].
   Return JSON only:
   {
     'substitutes': [
       {
         'name': 'substitute name',
         'compatibility': 'Drop-in replacement|
                           Minor code changes|
                           Significant changes',
         'codeChanges': 'what changes needed',
         'tradeoffs': 'what you gain or lose',
         'available': boolean (is it in 
                      user inventory)
       }
     ]
   }"

  Results shown as 3 substitution cards:
    
    If 'available' = true:
      Green border + "In your inventory!" badge
      "Use This Instead" button
        → Updates project component
        → Triggers AI to update 
          affected code in IDE

    If 'available' = false:
      Normal card
      Component name + compatibility level
      Code change note
      Tradeoffs text

  Compatibility color coding:
    Drop-in: green ("No code changes")
    Minor: yellow ("Small code changes")  
    Significant: orange ("Significant changes")

═══════════════════════════════════════
BACKEND ROUTES TO ADD
═══════════════════════════════════════

POST /api/components/add
  Body: { userId, name, category, 
          quantity, condition,
          purchasePrice, notes }
  → Inserts into user_components
  → Returns { component }

GET /api/components/:userId
  → Returns all user components
  → Ordered by added_at desc

PUT /api/components/:componentId
  Body: { updates }
  → Updates component row
  → Validates ownership

DELETE /api/components/:componentId
  Body: { userId }
  → Deletes if owned by user

POST /api/components/suggest-projects
  Body: { userId, components }
  → Calls Gemini suggestion prompt
  → Returns { suggestions }

POST /api/components/shopping-list
  Body: { projectId, userId, 
          components }
  → Calls Gemini shopping list prompt
  → Returns { shoppingList }

POST /api/components/substitutions
  Body: { componentName, platform,
          userInventory, projectContext }
  → Calls Gemini substitution prompt
  → Returns { substitutes }

POST /api/budget/save
  Body: { projectId, userId, 
          budgetLimit, components }
  → Upserts project_budget row
  → Returns { budget }

GET /api/budget/:projectId
  → Returns budget for project
  → Validates user owns project

PUT /api/budget/actual-cost
  Body: { projectId, componentId, 
          actualCost, userId }
  → Updates specific component 
    actual cost in budget jsonb
  → Returns { success }
