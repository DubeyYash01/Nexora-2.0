═══════════════════════════════════════
UNDERSTANDING THE CORE MECHANIC
═══════════════════════════════════════

Here is exactly how the system works:

1. User completes Step 2 (component selection)
   and clicks "Generate Build Plan"

2. Gemini generates a structured build plan:
   - 5 to 7 steps total
   - Each step has its OWN code block
   - Each step has its OWN libraries list
   - Code blocks are ADDITIVE — each step's 
     code builds on previous steps cleanly

3. User enters the Project Workspace:
   - Left panel: Step-by-step build plan
   - Right panel: Nexora IDE (Monaco Editor)
   - Bottom panel: AI Assistant (Prompt 4)

4. As user completes each step:
   - That step's code is PUSHED into the IDE
   - New code APPENDS to existing code cleanly
   - Required libraries appear in the 
     Library Reference Panel
   - The IDE shows exactly which lines 
     were just added (highlighted briefly)

5. By final step: IDE contains the complete, 
   working, structured codebase — built 
   incrementally, step by step.

GEMINI PROMPT FOR BUILD PLAN
────────────────────────────────────

Backend calls Gemini (gemini-1.5-flash) with:

---SYSTEM PROMPT START---
You are Nexora's IoT build plan generator.
Your job is to create a detailed, step-by-step 
build plan for an IoT project.

CRITICAL RULES FOR CODE GENERATION:
1. Generate code for Arduino/ESP32 platform 
   using C++ (Arduino framework)
2. Each step must have its own code block
3. Code must be ADDITIVE — each step's code 
   builds on top of all previous steps
4. Step 1 code is always the foundation 
   (includes all includes, defines, setup() 
   and loop() skeleton)
5. Each subsequent step ADDS to the codebase —
   never removes or contradicts previous steps
6. By the final step, all code combined forms 
   a complete working program
7. Write code as if it will be copy-pasted 
   into Arduino IDE and uploaded directly
8. Include helpful inline comments in code
9. Libraries must be real, installable 
   Arduino libraries

Return ONLY a valid JSON object.
NO markdown. NO explanation. NO code fences.
Just raw JSON.

Return this exact structure:
{
  "buildPlan": {
    "totalSteps": number,
    "estimatedTotalTime": "e.g. 2-3 hours",
    "platform": "ESP32" or "Arduino Uno" etc,
    "programmingLanguage": "C++ (Arduino)",
    "steps": [
      {
        "stepNumber": 1,
        "title": "step title",
        "objective": "what the user achieves 
                      in this step",
        "description": "detailed explanation 
                        of what to do and why",
        "duration": "e.g. 20 minutes",
        "phase": "Setup|Wiring|Coding|
                  Testing|Integration|Deployment",
        "whatYouLearn": "key concept this 
                         step teaches",
        "instructions": [
          "instruction 1",
          "instruction 2",
          "instruction 3"
        ],
        "wiringNotes": "important wiring or 
          connection notes for this step 
          (null if not applicable)",
        "safetyWarnings": [
          "safety warning if any (empty array 
           if none)"
        ],
        "code": {
          "filename": "main.ino",
          "language": "cpp",
          "content": "full cumulative code 
                      up to and including 
                      this step as a string.
                      Use \\n for newlines.",
          "newLinesAdded": "description of what 
                            code was added in 
                            this specific step",
          "highlightLines": [
            "line numbers that are NEW 
             in this step as integers"
          ]
        },
        "libraries": [
          {
            "name": "Library Name",
            "installName": "exact name to search 
                            in Arduino Library Manager",
            "purpose": "what this library does 
                        in one sentence",
            "isNew": true
          }
        ],
        "verificationCheck": "how user knows 
                              this step worked 
                              correctly"
      }
    ]
  }
}
---SYSTEM PROMPT END---

User message to Gemini:
"Generate a complete build plan for this IoT project.
Project: [projectTitle]
Description: [projectSummary]  
Components: [list component names]
Skill Level: [skillLevel]

Remember: code must be cumulative — each step

────────────────────────────────────
THE CODE PUSH SYSTEM
────────────────────────────────────

File: client/src/hooks/useCodePush.js

This is the core mechanic of Nexora.

When user clicks "Complete Step →":

1. Get current step's code.content from 
   buildPlan (the full cumulative code)

2. Get highlightLines array from current step

3. Call pushCodeToIDE(code, highlightLines):
   
   a. Set Monaco editor value to new code
   b. Calculate which lines are new 
      (compare with previous step's line count)
   c. Apply highlight decorations to new lines:
      Use Monaco deltaDecorations with 
      inlineClassName: 'new-code-highlight'
   d. Scroll editor to first new line:
      editor.revealLineInCenter(firstNewLine)
   e. After 1800ms: fade decorations 
      (remove highlight class gradually)

4. Update libraryList state:
   Add all libraries from this step where 
   isNew = true to the accumulated list

5. Update Supabase:
   projects table: current_step = stepNumber
   Mark step as completed in build_plan jsonb

6. Show success toast:
   "✓ Step [X] complete — code updated in IDE"

7. Auto-scroll left panel to next step

State to maintain in workspace:
  currentStep: number
  completedSteps: array of step numbers
  ideCode: string (current full code in IDE)
  accumulatedLibraries: array
  instructionChecks: object 
    { stepNumber: [bool, bool, bool] }

All state persists to Supabase on every change.
On workspace reload: restore all state.

BACKEND ROUTES TO ADD
═══════════════════════════════════════

POST /api/projects/generate-plan
  Body: { projectId, userId, 
          projectTitle, projectSummary,
          components, skillLevel }
  → Calls Gemini with build plan prompt
  → Saves build_plan to Supabase
  → Updates project status to 'in_progress'
  → Returns { buildPlan }

POST /api/projects/complete-step
  Body: { projectId, stepNumber, 
          userId, instructionChecks }
  → Updates current_step in Supabase
  → Updates build_plan jsonb to mark 
    step as completed
  → Returns { success, nextStep }

GET /api/projects/workspace/:projectId
  → Returns full project with 
    build_plan, components, ai_analysis,
    current_step, ide_code
  → Validates user owns this project

POST /api/projects/save-ide-code
  Body: { projectId, code, userId }
  → Saves current IDE code to Supabase
    (add ide_code text column to projects table)
  → Returns { success }
  → Called every 30 seconds auto-save 
    AND on every step completion

IMPORTANT RULES
═══════════════════════════════════════

1. The workspace is a FULL SCREEN experience.
   Hide the main sidebar from Prompt 1 
   when on /workspace route. 
   The workspace has its own navigation.

   Never interrupt the user with save dialogs.

5. If user refreshes workspace: restore 
   exactly where they were — same step, 
   same IDE code, same checkboxes.

6. On mobile: stack panels vertically.
   Steps panel on top, IDE below.
   Bottom AI panel hidden on mobile 
   (accessible via floating button).

7. After building confirm:
   - /workspace/[id] loads with all 3 panels
   - Build plan generates from Gemini 
     and displays correctly
   - Completing Step 1 pushes code to IDE
   - New lines highlight and fade correctly
   - Library tab updates after step completion
   - State persists on page refresh
