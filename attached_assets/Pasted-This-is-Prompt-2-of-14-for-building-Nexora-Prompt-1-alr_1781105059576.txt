────────────────────────────────────
GEMINI AI ANALYSIS — LOGIC
────────────────────────────────────

When user clicks "Analyze My Idea":

Call your Express backend at POST /api/projects/analyze

Backend receives: { idea, skillLevel, projectType }

Backend calls Gemini API (gemini-1.5-flash) 
with this exact system prompt:

---SYSTEM PROMPT START---
You are Nexora's IoT project analysis AI. 
Your job is to analyze an IoT project idea and 
return a structured JSON response.

Analyze the given idea and return ONLY a valid 
JSON object with NO markdown, NO explanation, 
NO code fences. Just raw JSON.

Return this exact structure:
{
  "projectTitle": "smart concise project name",
  "projectSummary": "2-3 sentence summary of what 
                     this project does",
  "howItWorks": "simple explanation of the working 
                 principle in 3-4 sentences",
  "estimatedComplexity": "Beginner|Intermediate|Advanced",
  "estimatedCost": {
    "min": number in INR,
    "max": number in INR,
    "currency": "INR"
  },
  "estimatedTime": "e.g. 1-2 weeks",
  "components": [
    {
      "id": "unique_id",
      "name": "component name",
      "type": "microcontroller|sensor|actuator|
               display|communication|power|other",
      "purpose": "why this component is needed 
                  in one sentence",
      "estimatedCost": number in INR,
      "isEssential": true|false,
      "alternatives": ["alternative 1", "alternative 2"]
    }
  ],
  "feasibility": {
    "costFeasibility": {
      "status": "good|moderate|high",
      "note": "one line explanation"
    },
    "complexityFeasibility": {
      "status": "good|moderate|high",
      "note": "one line explanation"
    },
    "availabilityFeasibility": {
      "status": "good|moderate|high",
      "note": "one line explanation"
    },
    "timelineFeasibility": {
      "status": "good|moderate|high",
      "note": "one line explanation"
    }
  },
  "risks": [
    "risk 1 in one sentence",
    "risk 2 in one sentence"
  ],
  "tips": [
    "helpful tip 1 for this skill level",
    "helpful tip 2"
  ]
}
---SYSTEM PROMPT END---

User message to Gemini:
"Analyze this IoT project idea for a [skillLevel] 
level user: [idea]"

Parse the JSON response.
Save the full analysis to Supabase projects table 
(create new project row with status 'draft', 
ai_analysis = parsed JSON, idea_input = original idea,
title = projectTitle from response).
Return the analysis to frontend.

If Gemini returns invalid JSON: retry once.
If retry fails: return a user-friendly error.

═══════════════════════════════════════
IMPORTANT RULES
═══════════════════════════════════════

1. All API calls from frontend go through 
   the Express backend — never call Gemini 
   directly from frontend (API key security).

2. Every Supabase operation must handle errors 
   gracefully with user-facing messages.

3. The component ownership state must persist — 
   if user refreshes, their toggles are saved.

4. All animations must use CSS transitions 
   or Framer Motion (if available) — 
   no janky instant state changes.

5. Mobile responsive — the component list 
   especially must work on small screens.

6. Do not hardcode any API keys in frontend code.

7. After building, confirm:
   - /dashboard loads with stats
   - /projects shows empty state for new users
   - /projects/new Step 1 renders correctly
   - Gemini API call works and Step 2 renders
   - Component toggles work and save to Supabase
